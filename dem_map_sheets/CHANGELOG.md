# Changelog

## 次期版（開発中・版番号未定）

- 出力DEMのNoData値を設定可能にした（設定キー `output_nodata`／パラメータ `OUTPUT_NODATA`、既定 -9999）。従来の固定値 -999999 は内部中間生成物の番兵としてのみ残る。run.json の `output_nodata` には実効値を記録する。
- パススルー経路（materialize）でセル値そのものを出力NoData値へ付け替えるよう修正（従来はメタデータのみで、入力の欠測値が標高として残っていた）。
- 入力ラスタの NaN・±inf セルを欠測として扱うよう修正（従来は数値として素通りし、優先側の NaN が下位の有効値を覆う場合があった）。
- 入力の欠測判定は入力自身の定義のみで行い、-9999/-999999 の推測はしない（定義の無いラスタのエラー停止は従来どおり）。
- 出力NoData値と一致する有効セルが入力にある場合、対象入力・衝突値・件数を示してエラーで停止する（当初は警告＋run.json記録だったが、統括の独立監査の指摘で停止保証に変更。点群（PDAL）入力でも、書出時に空セルを内部番兵で印付けすることで同じ停止が働く）。
- TerrainRGBタイルの欠測表現 -9999 はタイル仕様の固定値として維持し、出力NoData値とは連動させないことを明記。
- 点群入力（テキスト・LAS・LAZ）のNoData完全性を修正（Issue #9）。標高が出力NoData値または内部欠測番兵（-999999）と一致する点がある場合、補間方式（IDW・平均・最低値）やファイル形式を問わず、補間の前に対象入力・値・点数を示してエラーで停止する（従来は IDW・平均で周辺セルが汚染されたまま正常終了し、LAS の -999999 は無通知で欠測化されていた）。一致判定はGDALのNoData比較の許容幅（約 `4×FLT_EPSILON×|値|`、-9999 なら約 ±0.005）に合わせ、LASのスケール／オフセットによる丸めの影響を受けない。入力のNoData指定（NODATA）がある場合は、LAS/LAZでもその値の点を欠測として補間から除外する（従来はLASで無視されていた）。失敗時の run.json に `failure_detail`（入力・値・種別・点数）を記録する。点数の確認は、ファイルのZ範囲が該当値を含み得る場合だけPDALで厳密に数える。

## 0.2.1 - 2026-11-10

- QGIS 3.44.15 / Windows 11 における最終限定試験6区分に合格（合成データ）。GDAL 3.8.4／3.10 のCIで375件合格（8件スキップ）。
- 日本語パスの点群入力・出力、PDAL実行、一時作業領域の安全な確保、KEEP_WORK ON/OFF、キャンセル時の後片付けを改善・検証。
- `DEM_MAP_SHEETS_TEMP` の明示指定を優先し、共有 `C:\Temp` の自動作成と無確認の `%ProgramData%` 利用を廃止。
- キャンセル時の不完全出力警告を日本語・英語併記に変更。
- 回転ラスタの範囲、GDAL失敗時の後片付け、設定JSONの原子的保存、TerrainRGBの範囲外標高エラーを改善。
- 実業務LAS/LAZ、書込拒否TEMP、APIとGUIの処理時間差は未確認。鉛直基準の変換は行わない。

## 0.2.0 - 2026-10-07

- 2500図郭単位の重複DEM自動優先選定を追加。
- 優先順位を「計測年度（新）→精度（高）→グラウンド点密度（高）→図郭充足率（高）」の辞書順として実装。
- LEMメタデータの測量年を自動取得。
- ground_only LAS/LAZでは点数と範囲からグラウンド点密度を自動算出。
- 精度・点密度・計測年度を補完するCSV/JSON優先メタデータ台帳に対応。
- 図郭ごとの候補順位と採用根拠をrun.jsonへ記録。
- 旧来の「先入力優先／後入力優先」を維持。

## 0.1.0 - 2026-10-07

- CS Map Sheets v0.9.4を基礎にDEM作成専用プラグインとして分離。
- GeoTIFF/TIFF+TFW/IMG/ASC、GSI DEM ZIP/XML、XYZ/CSV/TXT、LAS/LAZ/COPC、森林航空レーザ成果に対応。
- 入力を共通CRS・セルサイズのFloat32 GeoTIFF DEMへ正規化。
- 入力別GeoTIFFと結合GeoTIFFを出力。
- TerrainRGB XYZ PNG（EPSG:3857、z/x/y）を出力。
- 入力順による重複優先規則とrun.json記録を追加。
- GSI `+x-y / startPoint` の現行解釈を採用。
